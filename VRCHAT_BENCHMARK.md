# Desktop Body benchmark

Run each of these 25 tests twice from the same starting setup, once with Codex operating Desktop Body and once with a fresh Inkling session. Judge both runs from the resulting VRChat frames, room log, or saved media. The [task manifest](harness/trials.json) gives the runner the same test IDs and criteria.

## Private starting areas

Both worlds use **Invite** instances. The Black Cat is the main benchmark site. Its vestibule, hallway desk, couches, main-floor bar, booth tables, and stage give the tests visible reference points. Butterfly Home serves as the world-join destination and the starting world for two tests. [The Black Cat world layout and native pickups](https://wiki.vrchat.com/wiki/Community%3AThe_Black_Cat)

Before scoring a new fixture, save a setup frame showing the starting position and facing direction. For an offscreen destination, save a second reference frame for the reviewer. Reuse the same spots, props, and camera placement for both operators. The listed locations and pickups still need a current in-game setup check before each first scored pair. Seasonal layout or placement changes require a new setup frame.

For the vestibule menu fixture, stay on the spawn side of the open doors. From the forward spawn view toward the reception desk, turn left to face the poster wall. Use the fixed wood trim, lower wall panels, and tile boundary as references. The digital posters rotate during a run. The first recorded setup frame is `build/vr-benchmarks/20261122-155211-311514-menu-05/start.jpg`.

The model gets the task sentence, starting world and area, and its current observation. On matched trials it also gets the selected task's starting checklist from the manifest. The checklist describes the setup the operator prepared.

The 25 tasks evaluate a shared set of controls. Inkling reads the current view, chooses a control or reusable workflow, checks what changed, and decides whether to continue. Workflows take parameters such as a world name or volume level, and the runner reports which workflows are available for the recognized panel. Each trial starts with fresh model context. The runner uses manual traces, screenshots, and review criteria for fixture verification and grading.

The current world-search workflow uses the same menu transitions for both mapped worlds and visual references to confirm the requested title and creator. Adding coverage for other worlds still requires a way to verify their search results and details. The manual aiming, click, movement, and camera controls are available as separate tools.

Stage each test before starting the timer. Reuse the same Invite instance when both runs can stay there. For a world-join test, a fresh Invite instance of the starting world can reproduce the setup. Record both instance numbers and verify that the starting area, pose, and menu match. For walking tests, record the start from eye level and a reference for the destination or return point. For pickups, record the prop, the start and landing spots, and which hand holds the prop at the start, if any. Use the same in-world object for both runs. If a landmark or prop is missing, mark the fixture unavailable and confirm a new setup before scoring a pair.

## Run one comparison

1. Open VRChat in VR mode and load an Invite instance. Reset the avatar, markers, props, and camera required by the test. Start Desktop Body with `python pilot.py --mcp`. If SteamVR's headset image is black and the VRChat mirror is live, start the pilot with `--game-mirror` as well. Close the SteamVR dashboard before starting the trial so controller buttons go to VRChat.
2. Start Inkling with `powershell -ExecutionPolicy Bypass -File start-inkling-ninfer.ps1`. The server listens on this PC at port 8097. Close that terminal or press Ctrl+C to stop inference.
3. Use `python vr_benchmark.py --list` for the reset and success criteria. Prepare the fixture, then run `python vr_benchmark.py menu-02 --operator manual` to drive the baseline through the shared controls. Enter one action per line, for example `{"tool":"set_ui_volume","arguments":{"percent":55}}`. Use `{"tool":"done","evidence":"Audio panel shows the new setting"}` to finish.
4. Restore the fixture to the same initial state, including menu panel, body pose, volume, avatar, camera, and props as applicable. Run `python vr_benchmark.py menu-02 --baseline "build/vr-benchmarks/MANUAL_RUN_DIRECTORY"` for a fresh Inkling attempt. The runner checks that the saved manual run used the same test, world, and view source, and checks the current framing before granting control. Verify small or hidden setup details, such as the saved volume and grip state, during reset. Inkling receives its own current image and actions. The baseline stays in the runner.
5. Use **Stop** or **Esc** in Desktop Body to revoke the trial immediately. Clicking the body preview also reclaims control. A stopped trial cannot send further movements using its old lease. You can stop the runner itself with Ctrl+C.

The live Stop check granted control to a test session, invoked Desktop Body's Stop command, and verified that a subsequent step using that session was rejected. See `build/vr-benchmarks/20261123-213608-950674-benchmark-stop-revocation-audit/`.

While recreating a setup, run `python vr_benchmark.py menu-03 --preflight --baseline "build/vr-benchmarks/MANUAL_RUN_DIRECTORY"`. It applies the same starting-view checks as the trial, reports the first view that needs adjustment, and saves the captured evidence. It runs without model inference or access to the controls and stays outside the scorecard. Verify hidden conditions such as the avatar's calibration state separately.
